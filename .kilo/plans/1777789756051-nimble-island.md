# Implementation Plan: React Frontend + Email Verification + Password Reset

## Overview

Three things to set up:
1. **React frontend** — Vite + React + TypeScript + Tailwind + shadcn/ui, replacing the existing plain HTML pages
2. **Email Verification** — on sign-up, send a verification link via Resend. Block sign-in if unverified.
3. **Password Reset** — forgot password flow with a time-limited reset link via Resend.

Email provider: **Resend** (`resend` npm package).

### Why This Structure

| Decision | Choice | Reason |
|----------|--------|--------|
| Separate `frontend/` dir | ✅ | Clean separation; frontend has its own `package.json`, `tsconfig.json`, and build pipeline |
| No pnpm workspaces | ✅ | Not needed at this scale; `pnpm --prefix frontend` commands from root keep it simple |
| Vite builds → `public/` | ✅ | Express already serves `public/` as static — zero backend change needed |
| React Router (SPA mode) | ✅ | All routes handled client-side; backend only needs a catch-all to serve `index.html` |
| shadcn/ui components in `components/ui/` | ✅ | Standard shadcn convention; CLI adds components here automatically |

### `frontend/src/hooks/useAuth.ts`

```ts
export function useAuth() {
  const getToken = () => localStorage.getItem('token');
  const setToken = (t: string) => localStorage.setItem('token', t);
  const clearToken = () => localStorage.removeItem('token');
  const isAuthenticated = () => !!getToken();
  return { getToken, setToken, clearToken, isAuthenticated };
}
```

## Part C: Database Schema Changes

### New model: `EmailVerification`

```prisma
model EmailVerification {
  id        String   @id @default(uuid())
  userId    String
  token     String   @unique   // store raw (not hashed, low-value temp token)
  expiresAt DateTime
  createdAt DateTime @default(now())

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([token])
  @@map("email_verifications")
}
```

### New model: `PasswordResetToken`

```prisma
model PasswordResetToken {
  id        String   @id @default(uuid())
  userId    String
  token     String   @unique    // store raw
  expiresAt DateTime
  used      Boolean  @default(false)
  createdAt DateTime @default(now())

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([token])
  @@map("password_reset_tokens")
}
```

## Part D: Backend Files to Create

### `src/lib/email.ts`
Resend client wrapper. Exports a single `sendEmail()` helper.

```ts
import { Resend } from "resend";

const resend = new Resend(process.env.RESEND_API_KEY);

export async function sendEmail(options: {
  to: string;
  subject: string;
  html: string;
}) {
  await resend.emails.send({
    from: process.env.RESEND_FROM_EMAIL!,
    to: options.to,
    subject: options.subject,
    html: options.html,
  });
}
```

## Part E: API Endpoints (all in `src/routes/user-auth.ts`)

### `GET /o/verify-email`
**Query:** `?token=<token>`

Logic:
1. Find `EmailVerification` record by token
2. If not found → `400 { error: "Invalid or expired verification link" }`
3. If `expiresAt < now` → delete record, `400 { error: "Verification link has expired" }`
4. Set `user.emailVerified = true`
5. Delete `EmailVerification` record
6. Return `200 { ok: true }`

---

### `POST /o/resend-verification`
**Body:** `{ email: string }`

Logic:
1. Find user by email (if not found, return `200` silently — don't leak existence)
2. If already verified, return `200 { ok: true }` silently
3. Delete any existing `EmailVerification` records for this user
4. Generate new token: `crypto.randomBytes(32).toString('hex')`
5. Create `EmailVerification` with 24-hour expiry
6. Send verification email via Resend
7. Return `200 { ok: true }`

---

### `POST /o/forgot-password`
**Body:** `{ email: string }`

Logic:
1. **Always return `200 { ok: true }`** (prevents email enumeration)
2. Find user by email — if not found, silently return
3. If user's email is not verified, silently return (can't reset unverified accounts)
4. Delete any existing `PasswordResetToken` for this user
5. Generate token: `crypto.randomBytes(32).toString('hex')`
6. Create `PasswordResetToken` with **1-hour** expiry
7. Send password reset email via Resend

---

### `GET /o/reset-password/validate`
**Query:** `?token=<token>`

Logic:
1. Find `PasswordResetToken` by token
2. If not found or `used === true` → `400 { error: "Invalid reset link" }`
3. If `expiresAt < now` → delete record, `400 { error: "Reset link has expired" }`
4. Return `200 { ok: true }` (page JS uses this to decide whether to show the form)

---

### `POST /o/reset-password`
**Body:** `{ token: string; password: string }`

Logic:
1. Validate `password.length >= 8`
2. Find `PasswordResetToken` by token
3. If not found or `used === true` → `400 { error: "Invalid reset link" }`
4. If `expiresAt < now` → delete record, `400 { error: "Reset link has expired" }`
5. Generate new salt + hash for the new password
6. Update `user.password` and `user.salt`
7. Mark `PasswordResetToken.used = true`
8. **Delete all `RefreshToken` records for this user** (invalidate all sessions on password change)
9. Return `200 { ok: true }`

## Part I: Security Notes

- `POST /o/forgot-password` **always returns 200** regardless of whether the email exists — prevents user enumeration
- Password reset token has a **1-hour** expiry
- Verification token has **24-hour** expiry
- **All refresh tokens are deleted** when a user resets their password
- Reset tokens are **single-use** (marked `used = true` immediately after consumption)
- Existing `EmailVerification` / `PasswordResetToken` records are deleted before creating new ones (prevents token accumulation)
- `onDelete: Cascade` on both models means tokens are auto-deleted if the user is ever deleted
