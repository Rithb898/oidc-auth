# Email Verification Link Opens Backend API Instead of Frontend

## Problem

When clicking the email verification link in Gmail, it opens the backend API (`http://localhost:5555/o/verify-email?token=...`) which returns JSON instead of rendering the frontend verification page.

## Root Cause

1. **APP_URL points to backend**: `.env` has `APP_URL=http://localhost:5555`
2. **Backend returns JSON**: `user-auth.ts:13-38` returns `res.json({ ok: true })` instead of redirecting
3. **Frontend has the route**: `App.tsx:15` defines `/o/verify-email` route for `VerifyEmail.tsx`

## Solution

Modify `backend/src/routes/user-auth.ts` to redirect to the frontend after successful verification instead of returning JSON.

### Changes Required

**File: `backend/src/routes/user-auth.ts`**

1. Add a `FRONTEND_URL` environment variable (or reuse `APP_URL` for frontend)
2. On successful verification, redirect to `/o/verify-email?token=<token>&verified=1` or similar
3. On failure, redirect with error params instead of returning JSON error

### Alternative: Fix `APP_URL` Configuration

If the frontend runs on a different port (e.g., Vite dev server on port 5173), set `APP_URL` to the frontend URL:

```
APP_URL=http://localhost:5173
```

This way the email link opens the frontend directly, which then calls the backend API.

## Implementation Plan

1. Check if frontend runs on separate port
2. Either:
   - **Option A**: Update `APP_URL` in `.env` to point to frontend URL
   - **Option B**: Modify backend `/verify-email` endpoint to redirect to frontend after processing
